# What to report about an idea, and when to score

## Lead with facts

- **Whose it is.** his · endorsed · other · system. Never drop it, never guess it.
- **Links made by hand.** Count only what a person wrote, and say so.
- **Whether the tension line is filled in.** Some are empty.
- **Whether anything has happened because of it.** Quoted, ruled on, built with,
  written about, cited by an ARCHIE run. This is the strongest signal there is and
  almost nothing has it. Check `agents/archie/outputs/` and `backlog/` for the seed ID.
- **When it was last touched.**

## Scoring is allowed, with one condition

He lifted the no-scoring rule on 2026-09-09. The condition that stays: **say what the
score is for.** The seedbank README explains why: "A quality score is a judgment
relative to a purpose, and the purpose was not set." Set the purpose per case.

A score for "closest to being writable" is a different score from "most likely to be
his to claim." Name which one you are giving, and show the facts underneath so he can
disagree with the total. Never present a score as a fact about the idea.

## Always say the one action

Not "needs more evidence." Say the specific next thing: name one real example, ask him
the one open question, check whether the rule it predicted is being followed. His own
2026-08-13 review did this in a column called "one action to advance it." Match that.
