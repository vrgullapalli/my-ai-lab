# Contextual Voice

> **Base directory:** all relative paths in this skill resolve from `.claude/skills/contextual-voice/` (its own folder, where `voice-core.md` and `context-dials.md` live). Line added 2026-09-14 for the skill check.

Preserve the user's way of thinking on the page, not merely surface traits. The result should sound like the same person making different kinds of moves for different audiences.

## Start with the writing job

Infer the format, audience, purpose, stakes, and desired action from the request and source material. Ask only if an unresolved choice would materially change the result. Otherwise choose a sensible default and draft.

Before writing, read:

- [references/voice-core.md](references/voice-core.md) for stable voice rules, sentence patterns, story logic, and anti-patterns.
- The relevant section of [references/context-dials.md](references/context-dials.md) for the requested format.
- [references/evidence-updates.md](references/evidence-updates.md) only when incorporating new writing evidence or changing the voice model.

## Drafting priorities

1. Preserve the user's intended meaning. Do not add stronger claims, certainty, wit, or contrarianism than the evidence earns.
2. Lead with the point. Make the reader's situation recognizable before explaining the framework.
3. Move from the visible issue to the harder question underneath it.
4. Use plain language, short sentences, active voice, and contractions where natural.
5. End with a useful judgment, distinction, question, or next move. Do not manufacture a tidy conclusion.

## Contextual adaptation

Apply the stable core in every format, then tune compression, narrative, warmth, challenge, evidence, and polish using the format reference. Do not make an article read like website copy or a casual note read like an executive brief.

When the format is ambiguous, preserve the user's natural conversational register and avoid over-polishing.

## Editing behavior

- Diagnose before rewriting. Identify the idea, the job of the piece, and what is weakening it.
- Keep strong original phrases when they carry the user's thinking.
- Remove throat-clearing, repetition, generic consultancy language, and ornamental cleverness.
- Prefer a precise question over an inflated declaration when the evidence is incomplete.
- If asked for options, vary the underlying move or emphasis, not just synonyms.
- For client-facing work, make distinctions and implications explicit without adding technical density.

## Output

Return copy-paste-ready writing. Unless requested, do not explain the voice analysis or annotate every choice. For substantial edits, a short note about the most important change is enough.
