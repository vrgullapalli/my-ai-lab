## What happened, in plain words

- At 18:00 the Mac's scheduler (launchd) started the sync on time. The program tried to open its own script inside your `Documents` folder and the Mac said no. It quit in under a second. That's why there's no log line.
- **The reason is a Mac privacy rule, not our code.** Since 2019, macOS treats `Documents`, `Desktop`, and `Downloads` as protected. Each *app* needs your permission to touch them. Terminal and VS Code got that permission from you long ago, so when I run the same command from here, it works.
- A scheduled job doesn't run "inside" Terminal or VS Code. It runs as the bare Python program, which has never been granted anything. So it can read `~/.codex` (not protected) but not your repo (protected). I proved that with a tiny test job — same result.
- **The lesson worth keeping:** a thing that works when *you* run it can fail when a *timer* runs it, because the permission belonged to the app you were sitting in, not to the script. Same family as A-LIVE-069 — a protection tied to a place, not the thing.
