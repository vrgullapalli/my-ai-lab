**Claude** · `812c2598-ccdf-4102-bbf3-41e3a02ae530`

Yes. It is one of the most common slowdowns with any coding agent, mine included.

- **Why it happens:** agents re-read to be safe. They don't trust that they remember a file, so they look again. Every look is a tool call, and every tool call is another full round-trip with the whole history attached.
- **It gets worse over time, not better.** A long thread makes each call heavier, and a heavy thread makes the agent more likely to re-read because its own memory of the file is buried. It feeds itself.
- **It shows up in a few shapes:** re-reading before each question (what you saw), re-checking the same file before each edit, re-running a search it already ran, and re-verifying things it already verified.
- **The fix is always the same:** do the expensive reading once, write the result to a file, then work from that file in a fresh thread. Reading is cheap once; reading every turn is what kills it.
- **In this repo:** your "retrieve before asking" rule and the handoff files are already that pattern for me. Codex has the same rule in `AGENTS.md` but this task didn't use it.
