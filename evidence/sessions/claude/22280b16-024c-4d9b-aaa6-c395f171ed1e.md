> # 7. Severity
> 
> Severity represents **current operating consequence**, not architectural importance and not future priority.
> 
> Use:
> 
> ### Critical
> 
> Current evidence shows material exposure of:
> 
> * canonical state
> * consequential authority
> * security/confidentiality
> * unrecoverable loss
> * system-wide inability to operate safely
> 
> ### High
> 
> Current evidence shows:
> 
> * repeated consequential failure
> * major current capability obstruction
> * recurring state or evidence corruption
> * a failure affecting several workflows
> * a binding constraint materially violated

> ### Medium
> 
> Meaningful current weakness with:
> 
> * bounded workaround
> * limited blast radius
> * no immediate irreversible consequence
> 
> ### Low
> 
> Localized inconsistency, documentation debt, cleanup, minor friction, or bounded risk.
> 
> Do not use severity to decide implementation order.

> Phase 4 handles priority.

> # 11. AI-native classification of existing workflows
> 
> Classify only **existing or demonstrably operating applications** where classification adds useful evidence.
> 
> Use the agreed standard.
> 
> ## Automation
> 
> Qualifies when:
> 
> * objective stays substantially the same
> * application stays substantially the same
> * outcome stays substantially the same
> * AI or deterministic software improves speed, cost, consistency, reliability, scale, or effort
> * no materially new application or form of value appears
> 
> Test:
> 
> > Are we doing essentially the same thing for essentially the same outcome, with better execution?
> 
> ## AI-native Redesign
> 
> Qualifies when:
> 
> * underlying objective stays substantially the same
> * basic valuable outcome stays substantially the same
> * AI materially changes how the work operates
> * work disappears, moves earlier, becomes continuous, or shifts among human, AI, and deterministic software
> * the workflow is materially different because AI participates from the beginning
> 
> Test:
> 
> > Are we pursuing the same basic outcome through a materially redesigned way of working?
> 
> ## AI-native Innovation
> 
> Only classify an existing application as Innovation when all are demonstrated:
> 
> * materially new application
> * materially new valuable outcome
> * more than speed, cost, reliability, scale, breadth, coverage, or feasibility improvement
> * AI is material to why the application exists
> * evidence demonstrates value from the new outcome
> 
> ## AI-native Innovation Hypothesis
> 
> Phase 2 should **not nominate future Innovation Hypotheses**.
> 
> If an existing experimental application already produces a genuinely new application/outcome but value remains unproven, it may be described as an **existing innovation hypothesis**, provided the evidence directly supports that description.
> 
> Do not import later-phase candidates.
