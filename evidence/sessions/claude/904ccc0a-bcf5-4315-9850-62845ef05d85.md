**The answer in one line:** Context is a contract and a package, not a store. One written contract per kind of job says what it must know. A script fills what it can from State and the drivers and refuses what the contract forbids. The model picks the rest by meaning and says why. The package carries an adequacy state that lowers what the job may do.

**The number behind it:** today's State package for the brief is 262 KB and 504 items. The brief needs about twenty. Nothing today says which twenty, why, or what to do when one is missing.

The design is at [2026-09-13--context-v0-1-design.md](docs/reports/2026-09-13--context-v0-1-design.md). The twelve-field spec went into the definitions under context-assembly, the registry entry now names the design, and the architecture check passed with 0 findings.

**The five design-check answers**

1. Job: give a job the minimum context it needs now, with source, age, authority, scope, and kind of knowledge kept, and lower the action when context is not enough.
2. Covered today: Retrieval finds evidence, State says what is current, drivers say what matters. None picks the slice for a job or lowers an action. The map already holds context-assembly as planned; this is its v0.1.
3. AI-native test: without AI, context is a fixed file list per job, which is today's front door and the design AD-01 challenges. With AI, the slice fits the job and the moment, and the script keeps the judgment honest.
4. Standard: shared system. The contracts file follows the registry standard, the check follows the sensor standard.
5. New system: no. One contracts file, one script, one skill, two skill edits, one facts line, one append-only lineage file.

**Three decisions that need you**

1. **Trust as an action ladder.** A contract declares the job's level (observe, prepare, recommend, act). The script lowers it by rule when context is incomplete, conflicting, or blocked. The model may raise severity, never lower it. I recommend yes, because it is the one move that makes a warning change behavior.
2. **Where assumptions and corrections live.** As State lines, proposed or his word with an anchor, written by the consumer at close. Context keeps no store, and a correction persists without you restating it. I recommend yes; the other path is a per-run package that forgets.
3. **Who may write a contract.** Alfred writes and changes them. Your word is required for action level act, any scope but AI Lab, or a loosened prohibited list.

**Two ways forward.** The first is to rule on the three and freeze the five tests, then one implement-and-verify goal. I recommend this, because the tests are the contract.
