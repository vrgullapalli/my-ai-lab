- Approval prompts are all switched off (`approval_policy = { granular = { sandbox_approval = false, ... } }`). So it can't even *ask* to write. It just fails quietly.

**How to give it write access to one folder only**
- Codex has a newer "permission profile" system that does exactly this: a named profile where the repo is read-only and one subfolder is writable. Add to `~/.codex/config.toml`:

```toml
default_permissions = "cos-advisor"

[permissions.cos-advisor]
description = "Read the repo, write only to the Codex folder"

[permissions.cos-advisor.workspace_roots]
"~/Documents/my-ai-lab-v2/chief-of-staff" = true

[permissions.cos-advisor.filesystem.":workspace_roots"]
"." = "read"
"work/codex" = "write"   # <- whatever folder you pick
```

- `.git`, `.codex`, and `.agents` stay read-only no matter what. Codex can't touch history.
- Swap `work/codex` for the folder you want. It should already exist.
- Leave `sandbox_mode = "read-only"` alone; `default_permissions` takes over when set.

**Two things to watch**
- **Don't use plain `workspace-write`.** That makes the *whole* repo writable. `writable_roots` only adds folders, it never subtracts. The profile above is the only way to get "one folder, nothing else."
