**Codex** · `msg_076baa7a832e3587016a8e09e8823c87d098f0bfb1d933276d`

The simplest distinction is:

- **Operating model:** the design for how work should happen.
- **Operating system:** the working implementation that makes it happen repeatedly.

| Concept | Core question | Includes |
|---|---|---|
| Operating model | How will intent become outcomes? | Value, roles, authority, decisions, workflows, information, capabilities, controls, measurement, and learning |
| Operating system | How does that model function in practice? | People, routines, tools, technology, agents, data, rules, interfaces, and feedback loops |
| SOP | How should one particular task be performed? | Step-by-step instructions for a specific recurring activity |

For example, a restaurant’s operating model defines who it serves, how orders flow, who makes which decisions, how quality is controlled, and how performance improves.

Its operating system is the actual functioning combination of employees, schedules, kitchen stations, recipes, software, inventory routines, training, and management meetings.

An SOP for closing the kitchen is only one small component of that system.

“Standard operating model” isn’t a universally precise term. I would use it to mean a **reusable default model for a recurring type of organization or situation**, which can then be adapted to its specific owner, purpose, users, and context.

A useful test is:

> If we removed the tools and implementation, would the logic for creating value and governing work remain?

If yes, that remaining logic is the operating model. The working realization is the operating system.

The repository’s current canonical language captures this well:

> **Operating model:** The repeatable system through which intent becomes outcomes.  
> **Operating system:** The implemented and functioning realization of an operating model.

The systems lesson is that you should design the model before assuming you need to build a full system. Sometimes the smallest correct response is only a better workflow, decision rule, capability, or tool, not a new operating system.
